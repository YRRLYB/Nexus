# Nexus 后续优先级

## 当前定位

v0.4.0 继续围绕“设备优先的个人工作台”，不把第一阶段扩张成云平台。Windows 桌面、Linux / VPS 管理是首要验收对象；Windows / macOS / NAS 目标设备按能力降级。

## 建议接下来先做

1. **内嵌终端与会话管理**：用 xterm.js + 主进程 SSH 通道，支持会话标签、快捷重连、复制粘贴和终端尺寸同步。终端与 SFTP 统一指纹信任，避免反复跳出 PowerShell。先完善安全和中断行为，不做服务器侧代理。
2. **可恢复的文件任务**：目录递归传输、任务队列、取消、失败重试与校验。预览继续只读；远程文本编辑需要显式确认、备份和修改冲突检测，不能直接覆盖。
3. **真实设备兼容矩阵**：用 Ubuntu / Debian / Alpine、Windows OpenSSH、macOS 和一种 NAS 实测；Linux x86_64 / ARM64 探针部署使用隔离测试机。自动安装要有可观察的进度和失败结果，不能只凭服务启动宣称接入成功。
4. **备份与信任管理**：无凭据配置导入导出、带口令的凭据备份、主机密钥变化的核实与换钥界面。正式发布前完善签名和更新校验；不默认同步密码到云端。

## 再往后

考虑 Docker 容器详情 / 只读日志、状态变化通知和设备分组，而不是先做复杂编排、多用户或 3D 拓扑。若增加远程自动执行安装，至少包含脚本预览、版本 / 哈希、服务器身份核对、权限确认、取消与回滚策略。

公开源码不自动等于已有开源许可；正式开源前由作者选择许可证，并保留第三方资源的许可声明。
